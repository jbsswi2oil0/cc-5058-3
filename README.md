# 行为树演出运行时 · 三维舞台

自主表演角色的行为树运行时：角色在三维舞台中走位、面向目标、执行短动作，
组合节点驱动**真实异步操作**（不是打印成功）。包含完整演出场景：
演员 A 向演员 B 递交道具时被临时叫离，支持取消 / 暂挂两种抢占语义，
迟到回执幂等丢弃，黑板带作用域与版本，界面可暂停检查、重放输入、编辑行为树。

## 启动界面

无需构建。任意静态文件服务器即可：

```bash
cd 本仓库目录
python3 -m http.server 8080     # 或 npm run serve
# 浏览器打开 http://localhost:8080
```

打开后点「▶ 启动 / 重启」开演。Three.js 已 vendored 在 `vendor/`，离线可运行。

## 运行无头语义测试

```bash
node test/run-tests.mjs         # 或 npm test（76 项既有语义断言）
node test/hotswap-tests.mjs     # 100 项热换版断言
```

既有 76 项断言：生命周期、取消/暂挂、迟到回执幂等、缺键拦截、失败反馈、作用域版本、
等待计时、导航取消，全部逐步核对节点状态与角色真实位置。
热换版 100 项断言见「演出中的逻辑换版」一节。

## 界面怎么玩

| 控件 | 作用 |
| --- | --- |
| ▶ 启动 / 重启 | 用编辑器里的 JSON 重建行为树并开演（冷启动，全新运行器） |
| **⟳ 演出中换版** | **把编辑器里的新树热换进正在运行的演出：校验 → 迁移 → 交接，不重建场景** |
| 样例下拉 + 载入样例 | 把 v2/v3/v4 热换版样例填进编辑器（见下表） |
| ⏸ 暂停 / ⏭ 单步 | 暂停后可在树视图、黑板、日志里逐步检查每个节点状态 |
| 🔁 重放输入 | 重置后按原 tick 重新注入本次记录的全部输入（确定性重演） |
| 叫离 A（取消/暂挂） | 立即触发高优先级打断，分别走 abort / suspend 语义 |
| 抢占时刻 + 设定叫离 | 探针先无界面跑一遍，定位「递交开始 / 成交」tick，把叫离排在 递交前 / 传递途中 / 等待确认 / 确认之后 —— **同一棵树只移动抢占时刻**，看返场后谁拿着道具、哪句接词真正触发 |
| B 确认 | 手动给当前活跃递交操作注入确认回执 |
| 注入迟到回执×2 | 给最近被取消的递交 token 再补两份迟到回执，验证不会二次转交 |
| 封锁通道 | 让移动操作失败，观察失败反馈回行为树触发兜底台词与重试 |
| 行为节点编辑 | 改 JSON →「应用并重启」冷启动；或「⟳ 演出中换版」热换版（保留运行状态） |

所有控件都通过「输入队列 → 内核」生效（写黑板 / 注入回执），不直接改世界；
世界里的失败（如移动失败）以节点 FAILURE 反馈回行为树，由兜底分支处理。

## 演出中的逻辑换版（热换版）

热换版的图形入口是编辑器面板里的 **「⟳ 演出中换版」** 按钮：它读取编辑器 JSON，
对**正在运行**的 `Runner` 执行候选校验与状态迁移，然后原地替换 `runner.tree`。
世界、黑板、事件流、输入队列、道具占用全部保留，不重建场景。

### 三个样例（样例下拉 →「载入样例」→ 换版）

| 样例 | 改动 | 可核验的语义 |
| --- | --- | --- |
| v2 | 递交分支中插入一个新动作（整理衣领） | 已越过的插入点显式跳过；当前递交沿用同一 token；已完成动作不重播 |
| v3 | 删除「谢幕鞠躬」分支 | 被删动作明确退出、道具归还；边界定位到其父组合，其上祖先不重进 |
| v4 | 同一 `key` 把递交方向反转（A→B 改为 B→A） | 语义契约已变：**不继承旧进度**，旧递交取消、新节点重新进入 |

### 迁移决策（面板「热换版 · 迁移映射」逐节点展示）

每个节点在 JSON 中可带 **`key`（稳定身份）**。换版只按 `key` + **语义契约**（类型 +
所有影响行为的参数）匹配，绝不按节点序号或数组下标继承状态：

| 决策 | 含义 |
| --- | --- |
| 迁移进度 | 同 key 同契约的运行中节点：接手等待剩余时间 / 导航 token / 组合索引 |
| 沿用操作 | 外部动作（移动/面向/动画/递交）共用旧 token，**不签发第二份控制意图** |
| 保留终态 | 已完成的兼容动作保留 success/failure，**不重播已发台词、不重跑** |
| 退出后重进 | 同 key 但语义契约改变 -> 旧动作取消退出，新节点重新 enter |
| 已删除 | key 在新版消失 -> 运行中的动作取消、释放道具，并记入「被重置状态」 |
| 首次进入 | 新版新增节点 |
| 跳过 | 插入点在当前进度之前：演出已越过，本场不追补（显式记录，不静默） |

### 最近兼容表演标记

迁移递归向下，记录**最深的、其下有节点未能接管**的组合祖先，作为重放起点：
标记以上保留运行/终态，标记以下重新进入。换版报告 `replayBase` 与面板标题会显示该点。
若没有需要重进的节点（变化全在当前进度之下且可迁移），则无重放边界。

### 失败与副作用

- **候选校验无副作用**：只构建候选树做静态检查（演员/道具引用、`key` 唯一、
  黑板契约与写入类型），不 enter、不签发操作、不推进世界。
- **换版失败保留旧树**：校验不过时 `runner.tree` 原样保留并可继续演到结束，
  面板与日志显示 `换版被拒：<原因>`。
- **外部动作政策明确**：可迁移 -> 同一 token 继续；不可迁移/被删 -> 取消并归还道具；
  绝不会同时留下两份控制意图。

### 命令行/无头核验

```bash
node test/hotswap-tests.mjs    # 100 项热换版断言
node test/run-tests.mjs         # 76 项既有语义断言（固定树执行仍成立）
```

热换版测试覆盖：候选校验无副作用、换版失败保留旧树、按 key 而非序号迁移、
等待进度迁移、继续外部动作不重发、删除运行分支释放道具、同 key 语义改变不继承、
连续提交新树、场景对象身份不变、固定树基线不受影响。

### JSON 中怎么写

```jsonc
{ "type": "moveTo", "key": "main.moveB", "name": "走向B", "actor": "A",
  "target": { "actor": "B", "offset": { "x": 0, "z": 1.4 } } }
```

- `key` 仅在**需要跨版本保留进度**的节点上写；不写 key 的节点换版时视为新节点，不会迁移。
- 黑板键在条件/写黑板节点里用 `bbKey` 指定（`{"type":"setBlackboard","bbKey":"calledAway","value":false}`）。
- 黑板契约在 `src/scenario.js` 的 `BLACKBOARD_CONTRACT` 中声明（键 → 期望类型）；候选校验据此拦截类型改变。

```
test/hotswap-tests.mjs  100 项热换版断言
```

## 关键语义

**生命周期**：节点 `idle → running → success/failure`；`enter` 只在进入时执行一次，
动作在 `enter` 里签发唯一操作 token，running 期间每个更新步只查询该 token，
绝不重复启动（树视图「入/出」计数与日志可核对）。

**抢占（取消）**：反应式选择器每步重评守卫。高优先级「叫离」成立时按黑板
`interrupt.mode` 处理当前分支：`cancel` 取消旧导航/动画/递交意图，
道具归还递交人，子树回 idle，返场后整段重演（重新走位、重新递交、新 token）。

**抢占（暂挂）**：`suspend` 保留节点与操作现场（同一 token），占用仍归递交人；
暂挂期间到达的回执被扣留，恢复后按序应用一次，重复回执丢弃。

**回执幂等**：回执按 token 路由。已取消/已完成的 token 收到的迟到回执一律
丢弃并记入日志（`receipt-drop`），无权改变道具占用——打断期间到达的两份
完成通知不会再转交一次。确认之后，递交动作进入时查到道具已在接手人手中，
幂等成功，不再签发新操作，演出沿新持有人继续。

**黑板**：键有声明层（作用域链），内层可读外层、写回落到声明层，局部键不泄漏；
每次写推进版本；条件/台词用 `require` 严格读取，缺键判 FAILURE 并记日志，
不会被默认真值悄悄放行。

**失败反馈**：移动操作失败（通道被堵）→ 节点 FAILURE → 选择器走兜底分支
（台词 + 等待 + 恒失败）→ 重试装饰器重新尝试，疏通后演出继续。
